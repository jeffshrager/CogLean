\note{
This talk is about CogLean, a way of stating cognitive theories so that what follows from them can be checked, compared and accumulated. The vehicle is Lean, a programming language that is also a proof checker, but you won't need to read any Lean today. I'll describe the problem, what the library contains, how it is organized around laws rather than individual models, two examples, a related approach, and where it falls short of mathematics. The library is open source, on GitHub.
}

\begin{frame}{The problem}
  Cognitive theories are stated in prose, in simulation code, or as equations fitted to data.
  \bigskip
  \begin{itemize}
    \item What follows from a theory's \emph{core assumptions}, as distinct from its parameter settings or implementation details, is rarely checked.
    \item A simulation shows that a model \emph{can} produce a result, with these parameters and these stimuli.
    \item It doesn't show which assumptions produced it, whether it survives other parameters, or whether a rival theory would produce it just as well.
  \end{itemize}
\end{frame}
\note{
Most of our theories live in prose, in simulation code, or as equations fitted to data. When we evaluate them, we usually run a model with particular parameters on particular stimuli and compare the output with data. That tells us the theory can produce a result. It doesn't tell us which of the theory's assumptions produced it, whether it would survive a different choice of parameters, or whether a rival theory would produce it just as well. Those are exactly the questions we care about when we compare theories, and they are rarely answered.
}

\begin{frame}{Three kinds of evidence a theory can give}
  \small
  \begin{tabular}{p{0.3\linewidth}p{0.3\linewidth}p{0.3\linewidth}}
    \toprule
    \textbf{One run} & \textbf{Every run} & \textbf{Every model satisfying the postulates}\\
    \midrule
    one model, one parameter setting & one model, all its executions & all models the theory allows\\
    the theory \emph{can} do it & that model \emph{always} does it & the postulates \emph{entail} it\\
    simulation & model checking, sweeps & proof\\
    \bottomrule
  \end{tabular}
  \bigskip

  CogLean is built around the third kind, and keeps the other two in the same language.
\end{frame}
\note{
It helps to separate three kinds of evidence. One run: one model, one parameter setting; the theory can do it. Every run: one model in all its executions, by exhaustive search or parameter sweeps; that model always does it. And every model the theory allows: the postulates entail it. That third kind is a proof, and it's what CogLean is built around. A proof tells you which assumptions matter, because it uses some postulates and not others, and it distinguishes what a theory can do from what it must do. Simulation stays essential for exploring and fitting, and experiments with people still decide whether the assumptions are right.
}

\begin{frame}{Why Lean}
  \begin{itemize}
    \item \textbf{One definition, run and proved.} The same definition of a memory can be \emph{run} on an experiment's stimuli and \emph{proved about} for all stimuli. The simulation and the theory can't drift apart.
    \item \textbf{Checked.} Every proof step is checked by a small trusted kernel.
    \item \textbf{General.} A theorem can quantify over all nets, all parameter values, all stimulus lists.
    \item \textbf{Cumulative.} Like Mathlib for mathematics: definitions made once, theorems imported rather than re-derived.
  \end{itemize}
  \bigskip
  \textit{The guarantee is relative.} Lean checks that a theorem follows from the definitions, not that the definitions capture the theory, still less that the theory is true of people.
\end{frame}
\note{
We use Lean, which is both a programming language and a proof checker. That matters because the same definition, say of a discrimination net, can be run on an experiment's stimuli and proved about for all stimuli, so the simulation and the theory can't drift apart. Every proof step is checked by a small trusted kernel. Theorems can quantify over all parameter values. And the library is cumulative: definitions are made once and reused. One caution, which I'll come back to: Lean checks that theorems follow from the definitions, not that the definitions capture the theory.
}

\begin{frame}{What is in the library}
  \begin{itemize}
    \item \textbf{CogLib}: shared constructs (feature codes, exact probability distributions, discrimination nets, sampled retrieval, attention) and theory-neutral phenomena.
    \item \textbf{EPAM} (Feigenbaum): discrimination-net learning. Stimulus generalization, oscillation, retroactive inhibition, learning to criterion, the serial position effect: all proved. A published serial-anticipation run is reproduced (33--34 of 34 responses agree).
    \item \textbf{Strategy choice} (Siegler \& Shrager): distributions of associations. Retrieval is used with probability $1-(1-R)^n$; and a finding: a more peaked distribution can \emph{raise} overt strategy use.
    \item \textbf{Multi-digit addition}: the two combined, with 18 predictions neither makes alone. Built as an \textbf{application}: library mechanisms wired together (recognize, retrieve, else solve the columns with single-digit trials), with no new mechanism and no answer given.
  \end{itemize}
\end{frame}
\note{
Here's what is in the library now. CogLib holds the shared constructs: feature codes, exact probability distributions, discrimination nets, sampled retrieval and attention, along with phenomena stated without reference to any theory. On top of it sit three theories. EPAM, Feigenbaum's discrimination-net model, where stimulus generalization, oscillation, retroactive inhibition, learning to criterion and the serial position effect are all proved, and a published simulation run is reproduced. The distributions-of-associations model of strategy choice, where proof turned up something surprising: a more peaked distribution can actually raise overt strategy use. And a model of multi-digit addition that combines the two. That last one is really an application: it's built by wiring library mechanisms together, recognition, then retrieval, else a problem solver that works the columns with single-digit trials, with no new mechanism and nothing handed the answer.
}

\begin{frame}{The generality problem}
  There are a great many specific models: EPAM, ACT-R, SAM, REM, MINERVA~2, TODAM, connectionist networks\ldots
  \bigskip
  \begin{itemize}
    \item Formalizing them one at a time doesn't scale.
    \item A pile of formalized models doesn't say what any two of them \emph{disagree} about.
    \item And none of them is ``true'': unlike mathematics, there's no settled foundation to build on.
  \end{itemize}
\end{frame}
\note{
Everything so far is about one model. But there are a great many models, such as EPAM, ACT-R, SAM, REM, MINERVA and connectionist networks, and formalizing them one at a time doesn't scale. Worse, a pile of formalized models doesn't tell you what any two of them disagree about. And unlike mathematics, none of them is simply true. So the question is how a general library should be organized.
}

\begin{frame}{Laws and families}
  \begin{columns}[T]
    \column{0.5\textwidth}
    \textbf{Laws}: small, theory-neutral properties of a memory.
    \begin{itemize}\small
      \item \emph{Certainty}: a just-studied item is retrieved for certain.
      \item \emph{Stability}: studying one item doesn't change another's retrieval.
      \item \emph{Order-freedom}: the order of study doesn't matter.
      \item \emph{Recency}: the later of two similar items is favoured.
      \item \emph{Stored-only}: nothing unstudied is retrieved.
      \item \emph{Determinacy}: retrieval has a single outcome.
    \end{itemize}
    \column{0.5\textwidth}
    \textbf{Families}: mechanisms, each formalized once with its parameters free.
    \begin{itemize}\small
      \item Discrimination (EPAM)
      \item Activation (ACT-R declarative memory)
      \item Strength with a criterion (DOA)
      \item Global matching (MINERVA~2)
    \end{itemize}
    \bigskip
    Predictions are proved \emph{from laws}, not from models.
  \end{columns}
\end{frame}
\note{
The answer is to organize the library the way Mathlib organizes algebra. Mathlib doesn't formalize every group; it states laws, like those of a monoid or a ring, proves theorems once per law, and lets particular structures inherit them. For memory, the laws are small properties a memory may or may not have: certainty, stability, order-freedom, recency, stored-only retrieval and determinacy. The families are mechanisms, each formalized once with its parameters free: discrimination, activation, strength with a criterion, and global matching. Predictions are then proved from laws, not from particular models.
}

\begin{frame}{The theory matrix}
  \small
  \begin{tabular}{lcccccc}
    \toprule
    & Certainty & Stability & Order-free & Recency & Stored-only & Determinate\\
    \midrule
    Discrimination & \has & \has & \lacks & \lacks & \has & \has\\
    Activation & \never & \never & \never & \has & \has & \never\\
    Strength & \lacks & \lacks & \has & \never & \has & \lacks\\
    Global matching & \lacks & \lacks & \has & \never & \lacks & \has\\
    \bottomrule
  \end{tabular}
  \bigskip

  Every cell is a theorem: a general proof that the law holds (\has) or fails (\never) at every parameter setting, or a counterexample at one setting (\lacks).
  Every law separates some families, and every family has its own row.
\end{frame}
\note{
Put the two together and you get a matrix. Every cell is a theorem. Has means a general proof that the family has the law at every parameter setting meeting the stated conditions; never, in bold red, means a general proof that it fails at every such setting; and lacks, in plain red, is a counterexample at one setting. The difference matters, because only the every-setting cells can be refuted by evidence. Every law separates some families, and every family has its own row. Global matching was added as a test of the laws, and on the first four it looked exactly like strength memory, which forced the stored-only law. Some of these laws are stated too narrowly, all-or-none where they should be graded; fixing that is the next piece of work.
}

\begin{frame}{What is true here?}
  In mathematics, a proved theorem is true. Here there are only competing theories. What can a library build on?
  \bigskip
  \small
  \begin{tabular}{p{0.32\linewidth}p{0.36\linewidth}p{0.22\linewidth}}
    \toprule
    Claim & Example & Status\\
    \midrule
    A law entails a prediction & stability $\Rightarrow$ practiced items stay practiced & proved, permanent\\
    A family has a law & discrimination nets have stability & proved, permanent\\
    People have a law & people lack stability in recall & empirical, revisable\\
    \bottomrule
  \end{tabular}
  \bigskip

  \normalsize
  Which theory is right follows from the second and third rows together.
\end{frame}
\note{
In mathematics, a proved theorem is true. Here we have competing theories, so what is true? There are three kinds of claim. That a law entails a prediction is proved, and permanent. That a family has a law is proved, and permanent. Whether people have a law is empirical, and revisable. Which theory is right follows from the second and third together, and the first two never expire, even if every model in the library is refuted.
}

\begin{frame}{A refutation spreads}
  \begin{itemize}
    \item If people lack a law, every family that has it at every setting is refuted at once, and every prediction proved from it loses its support, in every theory that uses it. A counterexample at one setting refutes nothing.
    \item The matrix carries a judged evidence row, kept apart from the theorems.
    \item Each judgment states its \textbf{bridge}: the assumption connecting what experiments measure (reports, decisions) to what a law is about (what memory retrieves).
  \end{itemize}
  \bigskip
  \textit{Example.} People endorse a prototype they never saw. That does not show they \emph{retrieved} it: a memory that returns a similar studied item also calls the prototype ``old''. The bridge is the missing piece.
\end{frame}
\note{
This structure has a useful property: a refutation spreads. If the evidence shows that people lack a law, every family that has the law at every setting is refuted at once, and every prediction proved from it loses its support, in every theory that uses it. A counterexample at one setting refutes nothing, since another setting may do what people do. So the matrix carries an evidence row for people, kept apart from the theorems. Each entry states its bridge, the assumption that connects what an experiment measures, which is a report, to what a law is about, which is retrieval. Endorsing a prototype you never saw, for instance, doesn't show you retrieved it. Often the next step in comparing theories is not more data but an explicit response model.
}

\begin{frame}{Example 1: confident errors, inherited}
  \begin{center}
  \begin{tikzpicture}[node distance=10mm]
    \node[box] (p) {problem};
    \node[box, right=of p] (r) {recognize\\(any memory)};
    \node[box, right=of r] (s) {search its\\associations};
    \node[box, below=8mm of s] (b) {backup};
    \node[box, right=of s] (a) {answer};
    \draw[arr] (p) -- (r); \draw[arr] (r) -- (s); \draw[arr] (s) -- (a);
    \draw[arr] (r) |- node[pos=0.25, left]{\scriptsize nothing} (b);
    \draw[arr] (s) -- node[right]{\scriptsize exhausted} (b);
    \draw[arr] (b) -| (a);
  \end{tikzpicture}
  \end{center}
  \begin{itemize}\small
    \item \textbf{Theorem}: a stranger taken for a familiar item with sharp associations is answered wrongly every time an answer is retrieved, with no more backup use than the familiar item.
    \item Proved once, for the composition. Inherited by multi-digit addition ($150+100$ taken for $100+100$) and by face naming (a stranger misnamed).
    \item From laws: any memory with determinacy, certainty and stability gives it. In the matrix, only discrimination.
  \end{itemize}
\end{frame}
\note{
Here is the first example. This composition, recognize with any memory, then search the recognized item's associations, else fall back on a backup, comes from our model of multi-digit addition. For it we proved a theorem about confident errors: a stranger taken for a familiar item with sharp associations is answered wrongly every time an answer is retrieved, with no more backup use than the familiar item itself. It's proved once and inherited by two tasks: 150 plus 100 taken for 100 plus 100, and a stranger misnamed as a familiar person. And from laws: any memory with determinacy, certainty and stability gives it, which in the matrix means only discrimination.
}

\begin{frame}{Example 2: an experiment derived from laws}
  Recency and order-freedom disagree. Derive the experiment that separates them.
  \medskip
  \begin{itemize}\small
    \item Two new items A and B; a probe equally similar to both.
    \item Study A then B, or B then A; then probe. Order effect $\Delta$ = how much more B is favoured after AB than after BA.
    \item \textbf{From laws alone}: order-freedom gives $\Delta = 0$; recency gives $\Delta > 0$; no memory has both.
    \item With a forced-choice response model, the prediction survives only if guessing is unbiased (or ``neither'' is equally likely in both orders).
  \end{itemize}
  \medskip
  \small
  \begin{tabular}{lccc}
    \toprule
    & ACT-R & Strength, MINERVA & EPAM\\
    \midrule
    $\Delta$ & $10/17$ (recency) & $0$ & $0$, or $-2$ (primacy)\\
    \bottomrule
  \end{tabular}
\end{frame}
\note{
The second example derives an experiment from laws. Recency and order-freedom disagree, so take two new items and a probe equally similar to both, study them in either order, and measure how much more the later item is favoured. From the laws alone, order-freedom predicts no effect, recency predicts a positive one, and no memory can have both. With a forced-choice response model, recency's prediction survives only if guessing is unbiased. And across the four families: ACT-R shows recency, strength and MINERVA show nothing, and EPAM, which has neither law, can show the most extreme primacy.
}

\begin{frame}{A related approach: SFT-GMA}
  \small
  Fisher, Houpt, Larue \& Schmidt (2025, \emph{J.\ Math.\ Psych.}): critical tests of ACT-R's core assumptions, by systems factorial technology (SFT) with global model analysis.
  \medskip
  \begin{columns}[T]
    \column{0.42\textwidth}
    \textbf{Shared}
    \begin{itemize}\footnotesize
      \item Separate a theory's \emph{core} assumptions from auxiliary choices.
      \item Verdicts per qualitative class, each with the theorem behind it.
      \item Their finding: ACT-R permits only serial perception within a modality, and data show parallel.
    \end{itemize}
    \column{0.56\textwidth}
    \textbf{Different}
    \begin{itemize}\footnotesize
      \item \textbf{Constrains}: processing structure in response times, not what memory retrieves.
      \item \textbf{Data}: SFT has a paradigm, diagnostics and published data; CogLean's link to data is judgment.
      \item \textbf{Scope}: one architecture, not a matrix of families.
      \item \textbf{Checking}: their proofs are careful prose; CogLean's are machine-checked.
    \end{itemize}
  \end{columns}
\end{frame}
\note{
We're not alone in wanting this. Fisher, Houpt, Larue and Schmidt, in the Journal of Mathematical Psychology this year, derived critical tests of ACT-R from eight core assumptions they propose, such as one production at a time, using systems factorial technology with global model analysis. They prove that ACT-R can only process two stimuli in the same modality serially, and published experiments show parallel processing, so some core assumption has to go. Like us, they separate core from auxiliary assumptions and give a verdict per class with its theorem; their tables look like one column of our matrix. The differences: they constrain processing structure seen in response times, we constrain what memory retrieves; their space comes with a paradigm, diagnostics and data, and ours doesn't yet; they analyze one architecture, we compare families; and their proofs are careful prose, ours are machine-checked. They also suggest that base-level activation should be monotone in uses and recency, just the graded law we need next. In the long run, I think executable, machine-checked, and a library that accumulates will win out, but only if it connects to data as well as SFT does. So I expect convergence.
}

\begin{frame}{Where this is weaker than mathematics}
  \begin{itemize}
    \item \textbf{Definitions are contestable.} A family is one formalization of a theory. We check that link with blind simulations and community implementations.
    \item \textbf{Laws are idealizations} and presuppose a representation (binary codes, feature-count similarity).
    \item \textbf{Families are flexible.} The informative facts are parameter regions, not single counterexamples.
    \item \textbf{Evidence is never final.} The empirical row will change; the proved rows won't, and the matrix says at once what follows.
  \end{itemize}
\end{frame}
\note{
Let me be clear about where this is weaker than mathematics. The definitions are contestable, which is why we do blind checks. The laws are idealizations, and they assume a representation. The families are flexible, so the most informative facts are about regions of their parameters, not single counterexamples. And the evidence is never final. But when it changes, the matrix tells you immediately what has been refuted.
}

    \item \textbf{More families as tests}: REM, a connectionist memory, CHREST, ACT-R with blending.
    \item \textbf{Observational semantics}: decision and report components, so laws about retrieval predict what participants say.
    \item \textbf{Beyond memory}: strategy choice, then production systems.
  \end{itemize}
\end{frame}
\note{
Next steps: learning across trials, where memory states themselves become random; graded laws, which will also tell us where in its parameters each family has each law; more families as tests, such as REM, a connectionist memory, and ACT-R with blending; decision and report components, so that laws about retrieval predict responses; and beyond memory, to strategy choice and production systems.
}

\begin{frame}{Take-home}
  \begin{itemize}
    \item Cognitive theories can be stated so that their consequences are \emph{proved}, for every parameter setting.
    \item The durable content is conditional: laws entail predictions; families have or lack laws.
    \item A matrix of families against laws tells you which experiments are worth running, and what a result refutes.
    \item The value is not just that EPAM, ACT-R and others can each be formalized, but that results about one component can be combined with results about another to give predictions none of them anticipated.
  \end{itemize}
  \bigskip
  \centering\small github.com/jeffshrager/CogLean
\end{frame}
\note{
So, the take-home. Cognitive theories can be stated so that their consequences are proved, for every parameter setting. The durable content is conditional: laws entail predictions, and families have or lack laws. A matrix of families against laws tells you which experiments are worth running and what a result refutes. And the real value isn't that each theory can be formalized; it's that results about one component can be combined with results about another into predictions that no single model anticipated. Thank you.
}
