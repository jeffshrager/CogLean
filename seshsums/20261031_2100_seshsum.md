# 2026-10-31 21:00: one memory for whole problems and column facts (OPEN_ISSUES #24, stage 1)

New: `MultiDigit/MultiDigit/SharedMemory.lean` (`MD.Shared`), imported by `MultiDigit.lean`.

## The model
- A digit pair `d + e` is coded as the problem `d + e` (`pairCode`), in the same code space as whole problems.
- `memFact` is `recognizeRetrieve` on digit pairs. It uses:
  - the same retriever and the same strength table `str` as whole-problem recall;
  - DOA's backup (`colBackup`: fingers, then counting), working on the pair as presented. This is a stated choice.
- `sharedBackup` is the solver with `memFact`. `strial` is a trial with one memory. The answer sets, criteria and search lengths of the two levels are separate.

## General results
- `memFact_self`: if a pair is recognized as itself, its column fact *equals* the DOA fact on its own associations.
- `sharedBackup_reduces`, `strial_reduces` and `strial_net_reduces`: under the same condition, the shared model is `Integrated.itrial`, so all of its theorems carry over.
- `mass_colBackup`.
- `column_confident_errors`: the confusion-error pattern for digit pairs, inherited from `RR.confident_errors`. `confused_column_gives_neighbours_sum`.
- Exact evaluation: `colBackupFast`, `memFastFact`, `sharedFast` (each proved `Same` as the original), plus `same_recognizeRetrieve`, `prob_strial_fast`, `columns_congr` and `prob_strial_tab`.
  - ACT-R's facts had to be certified once as literal distributions (`act00`, `act50`, `act11`), because `columns` recomputes facts per outcome.

## The setting
The memory studies 0 + 0, 5 + 0, 1 + 1, then 100 + 100 and 100 + 200. The strength table is `sstr`: `colStr` for the pairs and `Example.str` for the problems.
- **EPAM:** the net recognizes all five as themselves and takes 150 + 100 for 100 + 100. The values are identical to `Integrated` (`setting_epam_reduces`, `setting_epam_values`).
- **ACT-R** (`setting_act_pairs`, `setting_act_values`):
  - 0 + 0 calls up 5 + 0 with probability 15/197, and is answered 5 with 120/2167;
  - 150 + 100 calls up a digit pair with probability 83/1187;
  - retrieval answers 200 with about .396 (.425 unshared);
  - the solver is reached with about .407 (.362);
  - the solver is correct with about .385 (.656);
  - the overall answer is 250 with about .157 (.238);
  - errors on 100 + 100 are about .386 (.334).
