# 2026-10-31 19:00: confident errors as a phenomenon predicate

The refactor follows the implementation memo, "Abstracting the Confident-Errors Theorems".

**New: `CogLib/Phenomena/ConfusionErrors.lean`**
- `ConfusionErrorPattern trial wholeWrong isWhole isBackup x q` states three things, over any problem and outcome types, using only events the task names:
  - `q` is never answered wrongly by retrieval;
  - every retrieval answer to `x` is wrong;
  - backup use on `x` equals backup use on `q`.
- `ConfidentErrors … r` is the pattern plus a bound: backup use on `x` is at most `r`. The bound is an argument, not a fixed threshold.
- Supporting results: `confusionErrorPattern_iff`, the three projections, `.confident`, and `not_confusionErrorPattern_of_backup_ne`.

**Restated to conclude the predicate.** Hypotheses are unchanged and the names are kept:
- `RR.confident_errors`, `RR.confident_errors_of_laws`;
- `MD.AnyMemory.confident_errors`, `MD.confident_errors`;
- `Example.example_confident_errors`;
- `Integrated.integrated_confident_errors`, `setting_confident_errors`;
- FaceNaming's `epam_confident_misnaming` and `epam_confident_misnaming_of_laws`.

The proofs are the same chain as before; only the statements changed.

**New theorems**
- `RR.confident_errors_rate`: `ConfidentErrors`, with the bound `backupAfter` for `q`'s code.
- `Integrated.integrated_confident_errors_le`: the bound `(1 - r)^n`.
- `setting_confident_errors_bound`: the bound `1/46`.
- `setting_actr_not_pattern`: with ACT-R's memory at the setting, the pattern fails (383/1058 against 107/782). This is a counterexample, not just a hypothesis that fails.
